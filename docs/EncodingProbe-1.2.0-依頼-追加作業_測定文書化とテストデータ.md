## 1. 背景

第一次修正で、シングルバイトへの上書きの下限を 0.55 と決めた。その後、
`WorldLanguageTests` のテストデータに無いシングルバイト系言語 17 種 30 エンコーディングで追加測定を行い、
次が分かった。

- **通常の長さ（170〜230 バイト）では課題 1 の再発が無い。** 上書き経路に入った 43 件はすべて正しく救済された。
  経路上の最低信頼度はロシア語 KOI8-R の 0.574（70 バイト、ja-JP）で、0.55 を上回る
- **短い行（28〜90 バイト）では部分的に再発する。** 112 件中、誤った救済が 7 件、救済されずに東アジアのまま残るものが 7 件。
  閾値を下げても解決しない（0.5〜0.55 の間はアイスランド語 28 バイトの 1 件だけで、しかも誤った `ibm852` として救済される）。
  UTF.Unknown の短文での信頼度と精度が限界である
- **多くの言語では 0.55 ではなく 0.5 が効いている。** `0xFF` のように東アジアの判定がすべて拒否するバイトを含むテキストは
  独自判定が「判定不能」になり、上書き経路に入らずに採用の下限（0.5）だけで決まる。
  全長・×3 の 90 件のうち、経路に入ったのは 10 件だけだった
- 既存の東アジアのテストデータは 4〜15 バイト（日本語のみ 82〜125 バイト）と短い。
  `sample_big5.txt` は 8 バイト（你好世界）であり、拡張字は含まない

測定スクリプトと結果表はスクラッチにしかないため、リポジトリに残す。

## 2. 作業 A — 測定結果の文書化

`docs/EncodingProbe-1.2.0-調査-クロスチェック信頼度の測定.md` として記録する。含める内容：

- 測定の条件（言語・エンコーディング・長さ・カルチャー・検出モード・TFM）
- 表 A（シングルバイト系言語の正答時の信頼度）、表 B（東アジア旧マルチバイトでシングルバイトが返る場合の信頼度）
- 追加測定の結果表（長さごとの、経路に入った件数・正しく救済・誤って救済・救済されず）
- **0.55 を選んだ根拠。** 表 B の最大 0.51045 と表 A の最小 0.56949 の間に収まること
- 短文での限界（上の「部分的に再発する」の具体例を含む）
- **UTF.Unknown を更新したときは、この測定をやり直すこと。** 余裕が上下とも 0.02 程度しかないため
- 測定スクリプトを `tools/` に置く。`.ps1` は UTF-8（BOM 付き）で保存すること

`CLAUDE.md` の「旧マルチバイト判定の横取りとクロスチェック」節から、この文書を参照する。
UTF.Unknown の依存を上げる際の再測定の手順も、`CLAUDE.md` 側に 1 行で書いておくこと
（実測値だけを書いても、将来の更新時に気づけないため）。

## 3. 作業 B — テストデータの追加

### 3.1 シングルバイト系言語

| 追加するもの | 目的 |
|---|---|
| スペイン語、エストニア語 | 上書き経路に入って正しく救済される。回帰の検出 |
| ルーマニア語（`iso-8859-16`） | 緊急修正で直した経路の固定 |
| ウクライナ語（cp1251 / KOI8-U） | 「判定不能」になることの固定 |
| 短いアイスランド語の行、短い KOI8 の行 | 短文での既知の限界の固定 |

- **ベトナム語は採用しない。** .NET の cp1258 エンコーダーで往復しなかったため、サンプルのバイト列自体が信用できない
- 短文の限界を固定するテストには、**現在の挙動が正しいわけではない**ことをコメントで明記する。
  将来 UTF.Unknown が改善されたときに、このテストが落ちることで気づけるようにする

### 3.2 東アジアの長めのサンプル

繁体字と簡体字の **200 バイト程度**のサンプルを追加する。

既存の東アジアのテストデータは短すぎて、UTF.Unknown が系統を判定できない。
そのため、第二次修正で入れた繁簡クロスチェックが既存データでは一度も発動していない。
明示バイト列と香港サンプル（165 バイト）での検証は済んでいるが、通常のテストデータでも経路が通るようにする。

- 追加後、次が期待どおりになることを確認する
  - zh-CN カルチャーで繁体字の長文が 950 になること
  - zh-TW / zh-HK カルチャーで簡体字の長文が 936 になること
- 既存テストの期待値が変わる場合は、変更箇所を報告すること

## 4. 作業 C — 仕様書への追記

- **短文での既知の限界。** 概ね 28〜90 バイトの短いシングルバイト系テキストでは、
  誤ったエンコーディングとして救済される場合と、東アジアのまま残る場合があること。閾値では解決しないこと
- **上書き経路に入る条件。** 独自判定が「判定不能」を返す入力は上書き経路に入らず、
  採用の下限（0.5）だけで決まること。多くの言語がこちらに該当すること
- **UTF.Unknown が返すが .NET に無いエンコーディング**の扱い（緊急修正の依頼文 4 章と重複する場合は、そちらを優先）
