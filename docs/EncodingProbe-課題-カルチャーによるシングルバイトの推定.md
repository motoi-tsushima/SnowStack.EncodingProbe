## 1. 背景

### 1.1 発端（1.2.0 の手動確認）

イタリア語の windows-1252 のファイル（約 200 バイト、改行 LF）が、カルチャー it-IT でも判定不能（`CodePage = -1`、`EncodingWebName` は空）になった。
フランス語でも同様の結果が見られた。`file` コマンド（Git Bash）は `Non-ISO extended-ASCII text` を返した。
`Get-Content -Encoding 1252` のようにコードページを明示すれば正しく読める。

```text
Italiano
Pranzo d'acqua fa volti sghembi.
Caratteri propri: à è é ì í î ò ó ù ú « » °
Perché è così? Qual è la città più bella? Niente po' po' di meno!
Prezzo: 1.234,56 € — vecchio: 2.400.000 Lit.
```

切り分けの結果は次のとおり（カルチャー ja-JP / it-IT とも同じ傾向）。

| 入力 | 結果 |
|---|---|
| 上のファイル（約 200 バイト） | -1（UTF.Unknown の信頼度が採用の下限 0.5 に届かない） |
| 3 行目（文字の一覧）と 5 行目（記号・数字）を除いたもの（約 110 バイト） | 28591（iso-8859-1）。0x80〜0x9F を含まないので正しい |
| さらに `Prezzo: 1.234,56 € — .` を足したもの | 1252（windows-1252）。正しい |

**判定の成否は長さよりも内容に左右される。** 文字の一覧、記号・数字の多い行、その言語で通常使わない文字（イタリア語の `í` `î` `ó` `ú`）は、
統計による推定にとって不利な入力である。

### 1.2 原理的な制約

- シングルバイト系は、東アジアの旧マルチバイトのような構造上の規則を持たない。ISO-8859-1 は 256 通りのバイトすべてが有効で、
  windows-1252 も 5 バイト（0x81・0x8D・0x8F・0x90・0x9D）を除いてすべて有効である。同じバイト列がどのコードページとしても読める
  （0xE9 は cp1252 で `é`、cp1251 で `й`、cp1253 で `ι`）
- したがって判定は文章の統計（UTF.Unknown）にしか頼れない。UTF.Unknown の西欧語（Latin-1 系）の判定は、他の候補を押しのけないよう
  信頼度を低めに出す作りであり、短い文や不自然な内容では採用の下限を超えにくい
- 1.2.0 の現状の設計（判定できなければ -1 を返し、`-Encoding` / `-SourceEncoding` による明示指定を案内する）は正しい。
  判定不能を黙って特定のコードページに倒すと、誤ったときに文字化けがエラーにならずに起きるため

### 1.3 確認済みのこと

- UTF.Unknown は、0x80〜0x9F を含まない入力に iso-8859-1、含む入力に windows-1252 を返した。
  「iso-8859-1 と判定されたファイルの `€`（0x80）が C1 制御文字として読まれる」問題は、今回の入力では起きなかった。
  （保険として「iso-8859-1 の判定で 0x80〜0x9F があれば 1252 に格上げする」規則も考えたが、現状では不要と判断した。優先度は低い）

## 2. 提案: カルチャーによる推定（最後の手段）

ブラウザは文書のエンコーディングが分からないとき、**ロケールごとの既定のエンコーディング**を使う（WHATWG の HTML 標準にロケール別の表があり、
大半の西欧語は windows-1252）。Windows の ANSI コードページも同じ発想である。これを EncodingProbe の判定の最後に「推定」として加える。

### 2.1 アルゴリズム案

| 段 | 条件 | 結果 |
|---|---|---|
| 前提 | BOM・UTF-8・ASCII・東アジアの独自判定で決まらず、UTF.Unknown も採用の下限を超えなかった（何も返さない、.NET に無い名前を返した、を含む） | 現状は -1 |
| 1 | カルチャーの言語サブタグが西欧語の群（`fr` `it` `de` `es` `pt` `nl` `sv` `da` `no` `fi` `ca` `is` など。サブタグ分解は既存のカルチャーゲートと同じ規則） | 次へ。それ以外は -1 |
| 2 | 1252 で未定義の 5 バイトを含まない | 次へ。含めば -1 |
| 3 | ラテン文字らしさの検査に通る（2.2） | **1252 を返す** |

- ISO-8859-1 と 1252 のどちらを返すかは、常に 1252 とする。0x80〜0x9F が無ければ両者は同じ文字列になり、あれば 1252 でしか正しく読めない（ブラウザと同じ扱い）
- 既存の経路で救われている入力（UTF.Unknown が 0.5 を超える、上書き経路で救済される）には影響しない

### 2.2 ラテン文字らしさの検査

西欧語の文章では、ASCII の外の文字は単語の中にまばらに現れる（`città`、`Perché`）。
ロシア語の cp1251 やギリシャ語の cp1253 を 1252 として読むと、`Ðóññêèé` のように ASCII の外の文字が連続する。この違いで見分ける。

1252 として復号したうえで、例えば次の条件を課す（しきい値は測定で決める）。

- ASCII の外の文字が、ラテン文字（À〜ÿ など）か、よく使う記号（`€` `–` `—` `‘` `’` `“` `”` `«` `»` `°`）である
- ASCII の外の文字が連続する最大の長さが小さい（例: 3 文字以下）
- ASCII の外の文字の割合が低い

### 2.3 効く場面

- 1.1 のイタリア語のファイル（it-IT）
- 短いスペイン語（UTF.Unknown が `iso-8859-10` を返し、.NET に無いため -1 になる。1.1.0 仕様書 4.4 節）
- 利用者のカルチャーがラテン文字圏でなくても、`-Culture fr-FR` などを指定すれば効く

## 3. リスク

| リスク | 内容 | 対策 |
|---|---|---|
| カルチャーはファイルの言語ではない | 実行環境の言語であり、フランス語環境でロシア語のファイルを読むこともある | 2.2 の検査で、キリル文字・ギリシャ文字などを弾く |
| ラテン文字圏の中は見分けられない | ポーランド語（cp1250）をフランス語環境で読むと 1252 と推定され、`ł` が `³` になるなど一部が化ける | 2.2 では弾けない。**残る誤りの大半はここ** |
| 誤りが黙って起きる | 1252 はほぼすべてのバイトを復号できるため、推定が外れてもエラーにならない。`Convert-ProbedContent` の不正なバイト列の検査（N3）もすり抜ける | 既定で有効にするかどうかの判断（4 章） |

## 4. 決める必要のあること

1. **既定で有効にするか、明示的に有効にするか。**
   既定で有効ならブラウザと同じ振る舞いになる。明示的な有効化（例: `-Strategy` に新しい値を足す）なら、現状の「分からなければ -1」の方針を崩さない。
   **測定（5 章）の結果で決める。** 誤りがほぼ 0 なら既定で有効、中欧語の誤りが目立つなら明示的な有効化に留める
2. **対象の範囲。** 最初は西欧語（1252）に絞る。中欧語（1250）、キリル文字（1251）、ギリシャ文字（1253）などへの一般化は同じ枠組みで考えられるが、
   2.2 の検査を言語群ごとに作り直す必要がある
3. **結果の表し方。** 推定で決めた結果を、判定で決めた結果と区別して利用者に示すか（`EncodingInformation` に情報を足すか）。
   公開型の変更になるため慎重に判断する
4. **カルチャーと言語群の対応表を自前で持つか。** `TextInfo.ANSICodePage` は NLS と ICU で振る舞いが異なる可能性があるため、
   既存のカルチャーゲートと同じく、言語サブタグをキーにした表を自前で持つのが安全と考えられる

## 5. 測定の計画

既存の `tools/Measure-CrossCheckConfidence.ps1` / `tools/Invoke-CrossCheckMeasurement.ps1` を拡張して測る。

- 入力: 既存の X 群（18 言語 × 1 行・全文・全文 ×3）とテストデータに、**イタリア語**と 1.1 のファイル（およびその変形）を加える
- カルチャー: 西欧語のカルチャー（fr-FR、it-IT、de-DE、es-ES など）に加え、東アジアのカルチャー（`-Culture` を指定しない利用者の典型）
- 数えるもの:
  - 現状 -1 の入力のうち、推定で**正しく救われた**件数
  - 推定で**誤ったエンコーディングになった**件数。特に、ラテン文字圏の外の言語（キリル文字・ギリシャ文字・ヘブライ文字・アラビア文字など）と、中欧語・バルト語が 1252 と推定された件数
  - 判定不能の経路で、長さ・内容と成否の関係（ヘルプに書く目安にする）
- 2.2 の検査のしきい値は、この測定で決める
- 両ホスト（net48 / net10.0）で結果が一致すること
