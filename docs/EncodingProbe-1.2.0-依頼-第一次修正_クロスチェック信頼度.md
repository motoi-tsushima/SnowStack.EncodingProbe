# EncodingProbe 1.2.0 — 第一次修正：クロスチェックの信頼度下限（課題 1 の不具合修正）

- 作成日: 2026-09-22
- 位置づけ: 1.2.0 課題 1（東アジア以外の言語で旧マルチバイトと誤判定される）で入れた統合層クロスチェックの不具合修正
- 後続: 第二次修正（香港 Big5 対応 段階 1）はこの修正の完了後に別途依頼する。本依頼では繁簡の系統クロスチェックは実装しない

---

## 1. 不具合

`EncodingProbe.ShouldPreferUtfUnknown()` は、コードページの組み合わせ
（独自判定＝東アジア旧マルチバイト、UTF.Unknown＝シングルバイト）だけで差し替えを決めており、
信頼度の条件を持たない。信頼度の下限は `ApplyUtfUnknownResult()` の「0.5 以下なら CodePage = -1」だけである。

UTF.Unknown は短い漢字列やHKSCS 入りの Big5 に対し、0.5 前後の信頼度でシングルバイトを返す。
0.5 をわずかに超えた場合、正しい独自判定が覆されて文字化けする。

### 実測（PS 7.6 / PS 5.1 で同一結果）

入力は同内容の繁体字文（Big5）と簡体字文（GBK）を 6〜512 バイトで切り出したもの、各長さ 3 標本。
HKSCS 入りは Big5 文の中ほどに `88 62` と `FA 5F` を挿入したもの。

| 入力 | UTF.Unknown の結果 | 信頼度 | 現状の動き |
|---|---|---|---|
| Big5 / GBK 12 バイト以上 | 正しい系統（big5 / gb18030） | 常に 0.99 | 問題なし |
| **GBK 6 バイト（「这是一」）** | **tis-620** | **0.5104517…** | **0.5 を超えるため 874 に差し替わる（不具合）** |
| GBK 6〜8 バイト（上記以外） | iso-8859-7 / tis-620 / なし | 0.00〜0.47 | 捨てられる |
| Big5 6〜8 バイト | windows-1252 | 0.50 | 境界ちょうどで捨てられる |
| Big5+HKSCS 12〜512 バイト | windows-1252 / なし | 0.00〜0.50 | 境界ちょうどで捨てられる（余裕ゼロ） |

HKSCS 固有字が 2 字（4 バイト）入るだけで、512 バイトの文書でも UTF.Unknown は `windows-1252` を返す。
HKSCS 入りの文書は独自判定だけが頼りである。

---

## 2. 方針

閾値を役割で分ける。

| 定数 | 役割 | 値 |
|---|---|---|
| 採用の下限（既存） | UTF.Unknown の結果を答えとして使う（UtfUnknownOnly、独自判定失敗時の補完） | 0.5 超。**変更しない** |
| シングルバイトへの上書きの下限（新設） | 独自判定の答えを課題 1 の規則で覆す | 手順 2 の測定後に決定 |

独自判定がすでに出した答えを覆すには、答えとして採用するより強い根拠を求める、という考え方である。

## 3. 作業手順

### 手順 1：失敗する回帰テストを先に追加する

Combined モードで次を検証するテストを追加し、**現状のコードで 1 つ目が失敗すること**を確認する。

1. zh-CN カルチャーで、GBK の「这是一」（6 バイト）が 936 を返すこと（現状は 874 になるはず）
2. zh-CN カルチャーで、6〜8 バイトの GBK 簡体字が旧マルチバイト（GB 系）のまま維持されること
3. zh-TW と zh-HK カルチャーで、HKSCS 固有字（`88 62`、`FA 5F`）を含む Big5 文書が、
   12・16・24・32・48・64・96・128・192・256・384・512 バイトの各長さで 950 を返すこと（現状は通るが、境界上で守られているだけなので固定する）
4. zh-TW カルチャーで、6〜8 バイトの Big5 繁体字が 950 を返すこと（同上）

HKSCS のテストデータは .NET のエンコーダーでは作れないため、バイト列を明示して生成すること。
`tools/New-EncodingTestData.ps1` に生成処理を足すか、テストコード内でバイト列を組み立てる。
`.ps1` を変更する場合は UTF-8（BOM 付き）で保存すること。

### 手順 2：シングルバイト側の信頼度を測定して報告する

`WorldLanguageTests` が使うテストデータについて、UTF.Unknown の判定結果と信頼度（丸めない値）を記録し、次の 2 表を作って**報告で止める**（値はこちらで決める）。

- 表 A：シングルバイト系の言語（欧文、ロシア語、ギリシャ語、タイ語など）ごとの、正答時の最小信頼度
- 表 B：東アジア旧マルチバイトのテストデータに対して UTF.Unknown がシングルバイトを返したケースの、最大信頼度

net48（PS 5.1）と net10.0（PS 7）の両方で測ること。UTF.Unknown の参照バージョンが TFM で異なるため。

判断の基準は、表 B の最大値と上記実測の 0.5104… を十分上回り、かつ表 A の最小値を下回る値である。
両者の間に余裕が無い場合はその旨を報告すること（閾値以外の条件を検討する）。

### 手順 3：実装

- シングルバイトへの上書きの下限を定数として新設し、`ShouldPreferUtfUnknown()`（またはその呼び出し側）の条件に加える
- `EncodingInformation` が信頼度を持っていない場合は、統合層まで受け渡す経路を足す。公開 API は変えないこと
- `ApplyUtfUnknownResult()` の 0.5 は変更しない
- 第二次修正で繁簡の系統クロスチェックを同じ場所に足すため、判定を「採用する結果を返す」形に寄せておくと後が楽になる（必須ではない）

### 手順 4：確認

- 手順 1 のテストがすべて通ること
- 課題 1 の既存テスト（`WorldLanguageTests` の全カルチャー×全言語の直積を含む）がすべて通ること
- `tests/PSCompat/ProbedCompatScenarios.ps1` で PS 5.1 / 7.x の結果が一致すること

### 手順 2：信頼度の測定

net48（UTF.Unknown 2.6.0）と net10.0（2.7.0）で**測定値は完全に一致**した
（差は float の文字列化の桁数だけ）。

#### 表 A：シングルバイト系言語の正答時の信頼度

| テストデータ | UTF.Unknown | 信頼度 | 上書き経路に入るか |
|---|---|---|---|
| Thai / cp874 | tis-620 | **0.74330455** | **入る**（ja-JP で独自判定が 932） |
| German / cp1252・ISO-8859-1 | iso-8859-1 | **0.7416205** | **入る**（ja-JP で独自判定が 932） |
| French / cp1252・ISO-8859-15 | iso-8859-1 | 0.6747421 | 入らない |
| Polish / cp1250 | windows-1250 | 0.5949031 | 入らない |
| Polish / ISO-8859-2 | iso-8859-2 | 0.5949031 | 入らない |
| Russian / cp1251 | windows-1251 | **0.56948775** | 入らない |
| Russian / KOI8-R | koi8-r | **0.56948775** | 入らない |

全カルチャー（10）×全テストデータの直積を総当たりし、
独自判定が東アジア旧マルチバイトを返す＝上書き経路に入る組み合わせを調べたところ、
シングルバイト系言語で該当したのは上記 3 ファイル（いずれも ja-JP のとき）だけだった。
**現に経路へ入るものの最小信頼度は 0.7416205**、
経路に入らないものも含めた全体の最小値は **0.56948775** である。

#### 表 B：東アジア旧マルチバイトに対して UTF.Unknown がシングルバイトを返した信頼度

| 入力 | UTF.Unknown | 信頼度 |
|---|---|---|
| **GBK 6 バイト「这是一」** | **tis-620 (874)** | **0.51045173** |
| Big5 6〜8 バイト | windows-1252 | 0.5 |
| Big5＋HKSCS 12〜24 バイト | windows-1252 | 0.5 |
| `Chinese_Traditional/sample_big5.txt` | windows-1252 | 0.5 |
| Big5＋HKSCS 48・96 バイト | windows-1252 | 0.28125 |
| `Chinese_Simplified/sample_gb2312.txt` | iso-8859-16 | 0.3758409（.NET で解決できず CodePage = -1 になるため対象外） |
| `Korean/sample_cp949.txt` | ibm850 | 0.3019919 |

**最大値は 0.51045173**（依頼文の実測と一致）。

#### 余裕の評価

表 B の最大 0.51045 と表 A の最小 0.56949 の間に余裕がある。
現に上書き経路へ入るものだけを守るなら 0.7416 まで取れるが、
将来ロシア語やポーランド語が経路へ入っても守れるよう、
狭いほうの窓（0.51045 < x ≤ 0.56949）に収まる値を選んだ。

### 手順 3：実装（`SnowStack.EncodingProbe/EncodingProbe.cs`）

- 閾値を定数として明示し、役割で分けた
  - `UtfUnknownAdoptionThreshold = 0.5`（採用の下限。**値は変更していない**）
  - `SingleByteOverrideThreshold = 0.55`（上書きの下限。新設）
- `ApplyUtfUnknownResult` に `out double confidence` を足し、
  UTF.Unknown の信頼度を統合層まで受け渡す経路を作った。
  `EncodingInformation` にはプロパティを足していない（**公開 API に変更なし**）
- `ShouldPreferUtfUnknown` に信頼度の条件（`confidence > SingleByteOverrideThreshold`）を加えた
- `NormalDetectEncoding` から呼ぶ部分を `ResolveEastAsianLegacyCrossCheck`
  （採用する結果そのものを返す）に切り出した。
  第二次修正で繁簡の系統クロスチェックを足すときはここに並べればよい
