# 課題 — 配布物へのヘルプのコピーが手作業である

- 起票日: 2026-09-23
- 起票の経緯: 1.2.0 第三次修正（香港・マカオのヘルプの追加）で配布コピー先が 14 か所に増えたため
- 状態: **未着手**

---

## 1. 現状

配布用の `publish/SnowStack.EncodingProbe.PowerShell/` は手作業で構成している。
リポジトリで管理しているのは `.psd1` / `.psm1` / `core/…deps.json` だけで、
DLL と MAML ヘルプは `.gitignore` で除外し、ビルド出力を手でコピーして配置する（CLAUDE.md）。

MAML ヘルプは、PowerShell のエディションごと（`core\` = net10.0、`desktop\` = net48）に、
言語フォルダーの数だけ置く必要がある。

| 時点 | 言語フォルダー | コピー先 |
|---|---|---|
| 1.1.0 | en-US / ja-JP / ko-KR / zh-TW / zh-CN | 10 か所 |
| 1.2.0 | 上に zh-HK / zh-MO を追加 | **14 か所** |
| 用字付きのフォルダーを足した場合（`EncodingProbe-課題-ヘルプの用字付きカルチャー名.md`） | 上に zh-Hant-HK / zh-Hant-MO / zh-Hant-TW を追加 | 20 か所 |

言語が増えるたびにコピー先が増え、配置漏れは「そのカルチャーだけ黙って英語のヘルプになる」形で現れる。
`MamlHelpTests` はビルド出力を検査するので、配布物の配置漏れは検出できない。

## 2. 検討すること

- **ビルドで配布物を作る。** `dotnet publish` や MSBuild のターゲットで、
  net10.0 の出力を `core\`、net48 の出力を `desktop\` へ、言語フォルダーごと集める
- **スクリプトで配布物を作る。** `tools/` に配置用のスクリプトを置き、ビルド出力から DLL・依存 DLL・言語フォルダーを集める。
  言語の一覧は csproj の `<Content Include="<言語>\…">` から取る（一覧を二重に持たない）
- **配布物の検査。** 配置後の `publish/` に対し、`core\` と `desktop\` の両方に全言語のヘルプがあることを確かめる検査
  （スクリプトの最後、またはテスト）
- 既存の手順（`Copy-Item -Recurse` でビルド出力ごと配る）との関係。
  ビルド出力をそのまま配ると、不要なファイル（テスト用の依存など）が混じらないかも確認する
