# EncodingProbe 1.2.0 — 第三次修正：香港ロケールのメッセージとヘルプ（B 案）

- 作成日: 2026-09-23
- 前提: 第二次修正（香港 Big5 段階 1）が完了していること
- 参照: `docs/1.2.0-香港ローカライズ-調査報告.md`（以下「調査報告」）
- 方針の変更: 当初は香港用語で訳し直す案（C）を検討したが、**B 案（台湾版と同内容を香港に配置）に決定した**

---

## 0. 決定と、その理由

香港（zh-HK）・マカオ（zh-MO）向けに**独自の文面は作らない**。台湾版（zh-TW）と同じ内容を香港・マカオの行き先にも置く。

理由:

- Microsoft は Windows の zh-HK 言語パックの提供をやめており、zh-HK は「使用しない。zh-TW を参照」と案内している。
  **香港の Windows ユーザーが繁体字 UI を使う場合、実際に表示されるのは台湾向けの文面である**
- そのため参照できる zh-HK の IT 用語集が存在せず、香港用語で訳しても正しさを確かめる手段がない
- 香港の利用者は台湾式の用語に日常的に接しているため、台湾版の文面で実害がない

本修正の目的は、文面の内容ではなく、**香港のカルチャーからメッセージとヘルプに確実に届くようにすること**である。
将来、香港用語の文面を用意する場合は、本修正で整えた経路のファイルと辞書を差し替えるだけで済む。

## 1. 現状の問題（調査報告より）

| # | 問題 | 現状 |
|---|---|---|
| 1 | 香港・マカオのヘルプが英語になる | `zh-HK` / `zh-MO` フォルダーが無く、親（`zh-Hant`）も無いため en-US に落ちる。メッセージは繁体字なので食い違っている |
| 2 | 広東語が英語になる | `MessageCatalog` は `TwoLetterISOLanguageName == "yue"` を英語と判定する。第二次修正で判定側は `yue` を香港として扱うようにしたため、判定とメッセージで扱いが食い違う |
| 3 | `zh_HK` の結果がホストで変わる | PS 7（ICU）は簡体字、PS 5.1（NLS）は繁体字。「両ホストで同じ結果」という方針から外れる |

1 はフォルダーの追加で、2 と 3 は言語選択の作り直しで解決する。

## 2. 作業 A — `MessageCatalog` の言語選択をサブタグ分解に切り替える

### 方式

調査報告 1.2 の選択肢のうち、**「`ResolveEastAsianLegacyRegion` の結果をそのまま言語に写す」方式**を採る。
判定とメッセージで規則が食い違わない構造にすることが、問題 2 の根本的な対処になるため。

- `ResolveLanguage(CultureInfo)` から `TwoLetterISOLanguageName` と親チェーンの利用をやめる
- `culture.Name` を第二次修正の `EncodingDetector.ResolveEastAsianLegacyRegion(string)` に渡し、結果を言語に写す

| 判定の結果 | 言語 |
|---|---|
| Japanese | ja |
| Korean | ko |
| ChineseSimplified | zh-Hans |
| ChineseTraditional | zh-Hant |
| **ChineseHongKong** | **zh-Hant**（B 案。香港用の辞書は作らない） |
| None | en |

- **新しいメッセージ辞書は追加しない。** `Catalogs` の行も増やさない。
  香港は `ChineseTraditionalMessages` を使う
- 将来、香港用の文面を持つ場合は、辞書と `Catalogs` の 1 行を足し、上の表の香港の行を変えるだけで済むようにしておくこと
- 書式の適用に `CurrentCulture` を使う現状は変えない

### 期待される結果（調査報告 1.2 の実測表に対応）

| UI カルチャー | 現状 | 修正後 |
|---|---|---|
| `zh-TW` / `zh-Hant-TW` | 繁体字 | 繁体字（変化なし） |
| `zh-HK` / `zh-MO` / `zh-Hant-HK` / `zh-Hant-MO` | 繁体字 | 繁体字（経路が親チェーンからサブタグ分解に変わる） |
| `yue` / `yue-HK` / `yue-Hant-HK` | **英語** | **繁体字** |
| `yue-CN` / `yue-Hans-CN` | **英語** | **簡体字** |
| `zh_HK` | PS 7 は簡体字、PS 5.1 は繁体字 | **両ホストとも繁体字** |
| `zh-Hans-HK` | 簡体字 | 簡体字（用字優先。変化なし） |
| `zh-CN` / `zh-SG` / `zh` / `zh-CHS` | 簡体字 | 簡体字（変化なし） |
| `ja` 系 / `ko` 系 / その他 | 各言語 / 英語 | 変化なし |

## 3. 作業 B — MAML ヘルプに zh-HK と zh-MO を追加する

- `SnowStack.EncodingProbe.PowerShell/zh-HK/SnowStack.EncodingProbe.PowerShell.dll-Help.xml` を追加する。
  内容は zh-TW 版の**そのままの複製**（B 案）
- `zh-MO/` にも同じ内容を置く。`zh-MO` の親は `zh-Hant` であり、`zh-HK` フォルダーには届かないため
  （調査報告 1.3 の実測）
- ファイルの条件は zh-TW 版に揃える：UTF-8・**BOM あり**・XML 宣言 `encoding="utf-8"`・CRLF・行数一致
- `SnowStack.EncodingProbe.PowerShell.csproj` の `<Content Include=…>` に 2 行足す。
  34〜40 行目にある「zh-HK は今回未対応であり en-US へフォールバックさせる」というコメントを、現状に合わせて書き換えること
- 配布物（`publish/core/`・`publish/desktop/`）へのコピー先は 10 か所から 14 か所になる。`CLAUDE.md` の手順を更新する

### 本修正では行わないこと

- **用字付きのフォルダー（`zh-Hant-HK` / `zh-Hant-MO` / `zh-Hant-TW`）は追加しない。**
  PS 7 で `zh-Hant-TW` のヘルプが en-US に落ちる問題は香港と無関係な既存の不具合であり、
  フォルダーと配布コピーが大きく増えるため、別課題として起票する（6 章）
- `yue` 系のヘルプは en-US のままになる（`yue` の親は `yue` / `yue-Hant` で、中国語のフォルダーに届かない）。
  メッセージは繁体字になるため食い違いが残るが、Windows に広東語の UI が無いことから実害は小さい。既知の制限として仕様書に書く
